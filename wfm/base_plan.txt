   The trickiest part of semantic layers is converting the JSON "filters" array into actual Ibis filter expressions. Here 
   is the robust parser to handle that:def build_ibis_filters(model: SemanticModel, filters_json: list):                  
       """Translates JSON filters into Ibis/BSL programmatic filters."""                                                  
       ibis_filters = []                                                                                                  
                                                                                                                          
       for f in filters_json:                                                                                             
           # Get the actual Ibis column object from the BSL model                                                         
           # e.g., model.dimensions["employees.region"]                                                                   
           col = model.get_dimension(f["field"]) or model.get_measure(f["field"])                                         
                                                                                                                          
           op = f["operator"]                                                                                             
           val = f["value"]                                                                                               
                                                                                                                          
           # Map JSON string operators to Ibis Python methods                                                             
           if op == "==":                                                                                                 
               ibis_filters.append(col == val)                                                                            
           elif op == "!=":                                                                                               
               ibis_filters.append(col != val)                                                                            
           elif op == ">":                                                                                                
               ibis_filters.append(col > val)                                                                             
           elif op == ">=":                                                                                               
               ibis_filters.append(col >= val)                                                                            
           elif op == "<":                                                                                                
               ibis_filters.append(col < val)                                                                             
           elif op == "<=":                                                                                               
               ibis_filters.append(col <= val)                                                                            
           elif op.upper() == "IN":                                                                                       
               ibis_filters.append(col.isin(val)) # val must be a list                                                    
           elif op.upper() == "LIKE":                                                                                     
               ibis_filters.append(col.like(f"%{val}%"))                                                                  
                                                                                                                          
       return ibis_filters

   Pitfall 2: Date Formats Crashing SAP HANA                                                                              
   The Issue: The LLM outputs a filter: {"field": "shift_date", "operator": "==", "value": "Yesterday"} or "05-06-2026".  
   HANA requires strict YYYY-MM-DD or specific TO_DATE() casts.                                                           
                                                                                                                          
   The Fix:                                                                                                               
                                                                                                                          
   In your LLM System Prompt, add a hard rule: "All date values MUST be formatted exactly as YYYY-MM-DD." Provide the

   Let Ibis handle the HANA casting. Because you defined shift_date in BSL, Ibis knows it is a Date type and will         
   automatically wrap the string in HANA's TO_DATE('2026-05-06') syntax during compilation.                               
                                                                                                                          
   Pitfall 3: The Multi-Fact "Fan Trap" (Data Duplication)                                                                
   The Issue: Suppose you add a PAYROLL fact table to the model alongside TIMESHEETS. The LLM asks for {"metrics":        
   ["overtime_hours", "total_bonus_paid"]} grouped by employee_name. If BSL does a naive JOIN TIMESHEETS ON PAYROLL, the  
   rows will multiply, and overtime will inflate by 100x.                                                                 
                                                                                                                          
   The Fix: BSL is designed to handle a single Fact table model gracefully. If you need to query two different fact       
   tables (Timesheets and Payroll) in the same prompt, create two separate BSL models.                                    
                                                                                                                          
   Modify your Python routing code: If overtime_hours is in req_metrics, query the wfm_model. If total_bonus_paid is      
   requested, query the payroll_model.                                                                                    
                                                                                                                          
   If both are requested, execute both queries separately in parallel Python threads, return two DataFrames, and merge
